# Spec: automation（定时自动化）

## 范围

Zgo 的定时自动化（ZCode automation-experience 的调度核心）：按 cron 计划
在无人值守时运行 agent 提示，把结果记录回任务。第一部分覆盖调度与 CLI
（`zgo cron`）与服务内调度器；桌面任务面板为后续。

## 产品规则

1. 任务（Job）= 五字段 cron 表达式（分 时 日 月 周，本地时区）+ 提示 +
   工作区 + 可选模型 + 启用开关。字段支持 `*`、`*/n`、`n`、`a-b` 与逗号
   列表；周 0 与 7 均为周日。
2. 任务存于用户数据目录的 jobs.json（数组）；调度器每分钟重读文件——
   外部改动（CLI 增删改）下一分钟生效，无需重启。
3. 到期任务在调度器进程内运行：为每次运行新建会话、走正常 agent 回合
   （含权限门——无 asker 时按既有语义拒绝改动类工具，定时任务因此天然
   只读安全，除非任务进程装配了 asker）。同任务不重叠：上一轮未结束则
   本轮跳过并记录。
4. 运行结果记录在每个任务上：上次运行时间、状态（ok/error）与末条
   assistant 文本（截断到 2000 字节）。错误显式记录，不吞。
5. `zgo cron` 子命令管理任务：list（表格式输出，含下次到期）、
   add（参数：--schedule --prompt --workspace [--model] [--id]）、
   rm <id>、run <id>（立即触发一次，不等计划）、enable/disable <id>。
   直接读写 jobs.json。
6. 桌面应用启动时启动调度器（service.StartScheduler）；进程退出即停。
7. 桌面任务面板（菜单「定时任务…」）：任务列表（启用状态点、计划、下次
   到期、上次运行与状态），行内操作 ▶ 立即运行（异步，完成后刷新）、
   启用/停用、删除；新建表单（计划/提示/工作区（可浏览选择）/模型），
   计划与服务端同一校验。运行中的 agent 回合期间面板不可打开。

## 状态所有者

| 状态         | 所有者              | 说明                              |
| ------------ | ------------------- | --------------------------------- |
| 任务列表     | jobs.json（磁盘）   | 每分钟热重载；CLI 与调度器共用    |
| 运行中集合   | internal/schedule   | 任务 ID → 运行标志，防重叠        |
| 会话/转录    | agent.Session       | 每次运行独立会话，JSONL 正常落盘  |

## 验收场景

1. 解析：`*/5 * * * *` 每五分钟；`0 9 * * 1-5` 工作日九点；非法表达式
   （字段数、越界、坏 token）报错。
2. 下次到期：给定基准时间，Next 返回下一个匹配的分钟（含周/月末语义）。
3. 调度：到期任务触发 Runner、结果与时间记录在案；运行中不重复触发；
   禁用的任务不触发；文件变更后下一分钟重载生效。
4. 端到端：服务装配脚本 provider 后，一次到期运行产生完整会话转录，
   任务状态变为 ok 且摘要为末条回答；经真实分钟滴答调度器的路径同样
   覆盖（注入时钟 + 手动一跳）：到期任务触发并落转录，禁用任务不动，
   停止干净汇合。
5. CLI：add 写入 jobs.json；list 展示；rm/enable/disable 生效；run 立即
   执行一次并输出摘要。
6. 面板：打开即列出任务；坏计划在表单内报错不入库；启停/删除经服务生效；
   「▶ 运行」异步执行，运行中显示状态、完成后列表刷新。
